# 对话助手与统一记忆

更新：2026-10-19。本文件上半部分描述本轮实现；下方“历史验证”保留此前发布记录，不代表本轮已部署。

## 本轮全链路升级

### 移动端助手

- 助手成为全屏页面，顶部提供返回、当前旅程名称、新对话和更多菜单。使用 Base UI 管理焦点、Escape 和菜单；visualViewport 适配软键盘，48px 操作目标、16px 正文、减少动态效果支持。
- 更多菜单收纳旅程切换、历史、旅行记忆与助手设置。记忆入口通过 `onOpenMemory` 进入“我的”的同一页面；保留组件独立使用时的 MemoryManager 回退。
- `AgentDock` 兼容原有 props，新增 `openRequest:{id,prompt?}`、`onOpenMemory`、`onBodyChanged`、`onCollectionsChanged`。
- `AssistantBlock` 支持日期/选项提问、真实商品与地点、来源/地图链接、旅行清单、变更对比和查询状态。日期/选项点选直接作为下一条用户消息；历史普通 Markdown 消息继续安全渲染。
- 真实搜索卡可以存到待安排，或通过对话选择时间并生成修改预览。商品、图片、价格、事实和链接来自同一工具结果。只有确认后才更新行程。
- 停止回复通过 AbortController 取消读取和上游工作；关闭页面允许已开始的流继续，重新打开恢复持久消息。已改变版本的修改卡在界面禁用，服务端也拒绝。

### 执行循环与约束

`runAgentToolLoop` 最多六轮模型调用，每轮最多两项工具，旅行搜索最多四项查询。一次普通问答仍只调用一次模型。查询指纹归一化后复用成功或失败结果；当前旅程、身体和记忆读取保持实时。

注册的只读工具：`get_current_journey`、`read_memory`、`get_body_context`、`search_travel`、`check_route`、`validate_itinerary`、`propose_adjustment`、`get_collections`。写入通过服务器保存的 action 卡执行，包括既有行程操作、新增 collection/checkin/feedback。

- `check_route` 使用已核验的高德路线与实际活动区间计算缓冲，没有依据时返回未知。需要新的路线检索时，复用 `consult` 的调整 Workflow。
- 每一轮读取最新旅程；最终回复生成期间若版本变化，返回明确冲突。历史消息与旧工具结果不能覆盖当前版本。
- `useMemory=false` 高于请求内 `includeMemory=true`。记忆工具同时核对账号当前设置；WHOOP 原始数据不进入聊天或商品搜索。
- 身体上下文读取 `journeyBodyContext`，包含当天自评、近期反馈和待反馈的独立调整记录。聊天自评和反馈均需确认；反馈保存使用稳定 adjustmentId，更新后刷新今日页和调整页。
- tool blocks 只由服务器构造。模型只允许生成经过限制的日期/选项卡，不能伪造商品结果。新增来源通过持久 `verifiedOffers` 传给内部编辑服务，外部 API 不接受自行声明可信来源。
- 单项搜索失败保留已有结果并生成“部分检索暂未完成”状态卡。最终模型失败也保存已完成的来源卡，刷新可以恢复；同消息重试不会重复消耗查询。
- 总回复预算 240 秒，单次模型调用 60 秒；租约恢复阈值 300 秒避免有效多轮请求被错误回收。错误和取消不会自动重新发送原消息。

### 待安排与清单 API

新增迁移 `0014_journey_collections.sql`，按账号/旅程隔离。列表 `GET /api/journeys/:id/collections` 返回 `{items}`；`POST/PATCH` 所有写操作携带 `expectedVersion`。

- 添加：`{operation:'add',kind:'backlog'|'checklist',requestId,items:[{title,detail?,activityId?,sourceUrl?}]}`。来源只匹配本旅程已核验地点/服务，服务端补充图片与检索时间。
- 保存搜索结果：`{operation:'save_offer',messageId,offerId}`。从该账号、该旅程的持久 assistant blocks 中读取来源；不接受客户端传入的价格或链接。
- 完成标记：`{operation:'check',id,checked}`；移除：`{operation:'remove',id}`。
- 移出行程的活动通过同一 D1 batch 存入待安排。辅助函数同时支持版本、独立调整记录、手动变更唯一标识保护，竞争失败的请求不能写出孤立项目。

## 交互

- 各主页面固定「聊聊旅程」入口。手机抽屉支持半屏、上拉全屏、下拉收起/关闭，保留键盘和返回键操作；桌面为右侧面板，可展开。
- 对话明确绑定一段旅程，支持新建、切换、历史会话和删除。关闭抽屉不会取消正在读取的回复或后台规划任务。
- 对话创建草案、局部修改、重新规划、检索调整建议、版本恢复、忘记记忆。操作以服务器保存的卡片为准；仅创建、修改、恢复安排或应用候选时需要确认。普通问答、明确的记忆管理与只准备候选的请求不额外询问。
- 简单修改复用行程编辑服务。需要来源核验的请求复用规划任务和调整顾问；结果仍需按既有规则选择、确认。未完整的旅行条件保存为可继续补充的草稿。
- 当天剩余安排较密集且无休息时，可以出现基于行程事实的建议；不自动改变计划，不自动读取设备指标。
- 根据用户要求，本版不接语音输入或 ASR，不使用话筒或装饰性 Emoji。

## 数据与接口

- 迁移 `0009` 引入统一记忆、自动记忆设置、会话、消息、操作；`0010` 增加自动记忆变更的撤销凭证；`0011` 增加账号级记忆使用与 WHOOP 使用设置，均默认开启。
- 记忆分为长期、旅程、当天三种范围，支持有效期、停用、编辑、来源和版本冲突检查。档案备注、已有反馈记忆和达到阈值的偏好迁入/同步，删除标记防止历史资料重新导入。
- 当次疲劳不再累计成长期偏好；常住城市与旅行目的地分别记录。调整页可独立选择使用记忆。
- `GET/POST /api/agent/conversations`、`GET/DELETE /api/agent/conversations/:id` 管理按账号隔离的对话。
- `POST /api/agent/messages` 接收会话 ID、消息 ID、文字，记忆使用读取账号设置，返回 SSE 状态、文字和最终结构化回复。消息 ID 支持同内容重试；中断不会自动重复模型调用。
- `POST /api/agent/actions/:id` 接收应用/放弃，数据用途读取账号助手设置，按保存的操作执行，不接受客户端替换操作内容。行程版本变化会拒绝旧建议，重复应用不会重复修改。
- `/api/memory` 支持读取、新增和忘记；`PATCH /api/memory/:id` 编辑；`PATCH /api/memory/settings` 控制对话自动提取；`POST /api/memory/undo` 撤销自动新增或恢复自动修正前的内容，且不覆盖后续手动编辑。
- 对话模型复用标准百炼模型 API 配置，规划继续使用既有托管智能体与 Cloudflare Workflow。对话不接收 WHOOP 原始指标；设备数据仍在规划流程内按账号助手设置处理。请求使用 `store:false`。
- 修正 Cloudflare 运行时不支持的 `redirect:error`，改用 `manual` 并拒绝非成功响应，不向跳转地址转发授权头。
- 共享旅程状态 Hook 统一手动界面、顾问与对话结果。活动用稳定 ID 定位；固定预约、过去活动和未核验来源在服务器校验。

## 搜索边界与会话错误修复（2026-10-19）

- 本轮用户明确“只搜一次 / 只用语义搜索”时，服务端从当前原文提取查询次数及工具类型上限，在实际调用前验证。单次不能夹带多个查询，失败也不会自动切换工具；限制原因会返回给模型。受限轮不能通过 consult、plan 或 create 启动另一个检索流程。
- 检索回执的匹配说明直接呈现并保存到消息。真实来源不等于符合用户需求；空结果不呈现历史商品或伪造地点。服务匹配筛选由搜索模块提供，助手保留其局限说明。
- 用户明确“不读取身体记录或旅行记忆”时，默认上下文与后续工具均跳过对应数据库读取，模型上下文去除旧草稿身体自评字段，本轮也不自动保存记忆。账号全局记忆关闭具有最高优先级；单条消息不能重新开启。
- 点击“新的对话”清除上一段对话的错误。没有自动重建、自动重发或清空历史逻辑。既有历史会话 404 尚无稳定复现，不将此次修补声称为其根因修复。
- 33 项 Agent 回归通过，覆盖查询边界、工具拒绝原因、禁止绕过、回执持久化、隐私数据零读取、版本与来源保护。两轮真实模型对话的本地请求使用同一会话 ID，历史读取保持 200，无 DELETE 请求；此结果不推断生产历史 404 的原因。

## 最终动作格式的只读恢复

- 最终回复的动作/格式未通过校验时，在原有最多六轮中只允许一次纠正。此前未检索时，纠正可在既有预算内首次检索；已有检索尝试（包括失败）时不能重复或另开查询。相同查询缓存只返回已有回执。
- 纠正后的最终动作必须为空，记忆为空；正文由本轮服务端来源和状态生成。无法完成纠正时，仍保存并返回已核验卡片与未执行说明，没有实际检索时明确未完成，不能用模型原文声称找到或已修改。

- 最终追加正常只读分支的结果约束：无商品且查询失败/未知时，正文固定为“检索未完成”；真正空结果才说明没有匹配，合法问题卡保留。最终 39 项 Agent 回归、TypeScript 与相关 ESLint 全部通过。再次真实本地模型复测已返回“这次检索未完成，暂时没有可核验的匹配结果。未执行额外操作。”，done 与历史持久化正常，单条 fliggy_ai_search 回执保持 FLYAI_NOT_CONFIGURED。
