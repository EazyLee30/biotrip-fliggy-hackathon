# 飞猪检索链升级

更新：2026-10-19。本文件记录本次代码与契约测试，不代表已完成生产发布或八类真实上游验收。

## 工具与来源

已对照官方 `@fly-ai/flyai-cli@1.0.16` npm 发布包的参数映射，支持八种只读意图：

| 意图 | MCP 工具 | 核心条件 |
|---|---|---|
| 航班 | `search_flight` | 城市、日期、直达、最长时长、价格 |
| 火车 | `search_domestic_train` | 城市/车站、日期、直达、时长、价格 |
| 酒店 | `search_hotels` | 目的地、入住/退房、附近地点、价格 |
| 景点 | `search_poi` | 城市、关键词、官方景点类别 |
| 万豪酒店 | `search_marriott_hotels` | 目的地、日期、品牌关键词、附近地点 |
| 万豪套餐 | `search_marriott_packages` | 单一关键词、价格排序 |
| 通用商品 | `fliggy_fast_search` | 公开旅行关键词 |
| 语义搜索 | `fliggy_ai_search` | 公开旅行条件组成的简短查询 |

万豪品牌使用官方 CLI 实际支持的 `keyWords` / `--key-words`，不发送旧参考文档中 CLI 不支持的 `--hotel-brands`。

`VerifiedOffer` 保留商品名称、原始 HTTPS 来源、供应商价格、可选原图，并增加工具、检索时间、结构化事实。航班/火车名称由真实航段字段确定性拼接；`adultPrice` 与景点 `ticketInfo` 被明确解析。缺失的票价、时刻、图片保持缺失，不补造可售状态。

语义搜索的 JSON 字符串结果可解析；普通介绍文字、正文里的裸链接无法成为商品。链接必须是无凭据的公开 HTTPS 地址，拒绝本机/内部地址、IP、异常端口和显式密钥参数。图片继续限定供应商返回的阿里图片 CDN。事实来自成功工具返回，不等于 BioTrip 独立核验营业状态、实时余位或医疗效果。

## 调度与接口

- `searchTravel(accountId, intents, signal, requestKey?)` 接受一个意图或最多四个意图，按查询指纹去重，返回 `offers / receipts / searchedAt`。对话使用服务器已认证的账号和稳定的消息/工具调用标识。
- `POST /api/travel/search` 接受同样的意图 JSON，要求已登录且同源，支持 `Idempotency-Key`，响应不可公开缓存。它使用后台签名只读通道；托管规划继续优先走官方 Skill。
- 账户级查询回执保存已完成、空结果、失败和未确认状态。重试同一请求不再次调用供应商；改变条件却复用请求键会冲突。同一账号每小时最多发起 48 个新查询，单请求最多四个。
- 托管规划改用结构化酒店和 POI 搜索。调整顾问可传 `StageContext.searchIntents`，仅查相关类别；未提供时保留原有兼容行为。
- Skill 中后续查询失败时，保留此前成功及空结果。已经发起但缺少结果的查询保留“未知”，不自动重复；只补明确失败或尚未发起的查询。应用可观测的 Skill 调用与回退合计限制为四次，超出类别如实显示未核验。这不代表能够计量或阻止托管上游内部不可见的重试。
- 首个公开来源仍可流式展示。会话创建后立即保存清理回执，结束时通过 `waitUntil` 删除；失败由既有定时任务重试，不等待最长十秒的远程删除才返回规划。

## 数据边界

意图 schema 仅接受公共旅行条件，不接受账号、WHOOP、身体反馈或记忆对象；常见身体指标、健康评分、邮箱、手机内容会在查询校验阶段拒绝。对话应把身体需求转成“附近茶馆”“直达交通”等公开检索条件。关键词检查是防误传补充，不能被描述为对任意自由文本的完整敏感信息检测。

字符串与品牌数组使用相同的隐私内容校验；上游响应拒绝日志只记录结构和数值状态，不记录可能回显查询或凭据的错误正文。

迁移 `0015_tool_receipts_cleanup.sql` 增加账号隔离的短期搜索回执与会话清理队列。查询原文不落库；公开结果与哈希回执保留一天，账号删除级联删除搜索记录。会话清理失败记录保留到确认为删除或不存在，避免静默放弃清理。

## 验证

50 项相关回归通过，覆盖八类参数、航班/火车字段、酒店/POI/套餐事实、语义字符串、非法来源、同类多查询、部分失败去重、未知结果不重试、四次可观测预算、并发重试、账号隔离、限额、同源鉴权、清理失败重试与无请求上下文的定时清理。相关 ESLint 通过。

可靠性复查确认：搜索记录使用账户与请求键的复合主键，所有读取和更新均携带账户范围；查询执行权由数据库原子插入取得。后台删除有 `waitUntil` 与既有每小时定时任务两条执行路径，未确认删除的记录不会丢弃，租约避免并行定时任务重复执行。供应商缺失字段仍为空，商品事实未经过独立营业或库存核验。

本地未配置 FlyAI 签名凭据，因此本轮未发送真实搜索、未测量真实供应商首结果延迟，也未宣称八类工具生产调用全部成功。后续通过部署后的正常应用接口，以测试账号进行一至两次只读抽样验证；使用公开城市/日期，不提取登录凭据，不触发预订、付款或订单修改。

## 生产验收反馈后的字段与相关性修复

- 航班、火车的已知 `totalDuration` 数字及纯数字字符串增加分钟单位；航段数字用时增加分钟，未知文字与现有单位不重写。旧历史结果不迁移。
- 混合搜索的分类不再从查询中的“茶馆、餐食、按摩”等词推导。具体工具保持其真实类别，混合商品仅根据明确的酒店、景点字段作保守分类，其余为“旅行商品”。
- 对明确茶饮、咖啡、餐饮、按摩/SPA 的服务查询，要求来源产品标题或套餐信息包含对应场景证据；酒店/景点的地址与设施标签不能证明服务可单独使用。住宿类查询及以服务点为地标的酒店查询不套用此筛选。
- 没有匹配证据时返回空 offers 和可重放的 `SEARCH_NO_RELEVANT_MATCHES` 回执说明；有证据时仍提示座位、距离、营业状态与是否可单独使用未独立核实。此为上述明确服务场景的保守筛选，不宣称已解决所有开放式语义相关性。
- 仅来源的 `price`、`adultPrice`、`ticketInfo.price` 裸金额增加人民币符号；不把评分、ID 或描述中的数字推为价格，已有明确币种保持原样。

这一补丁使用合成的酒店、景点与服务商品响应复现验收反馈，没有新增真实付费调用。相关回归涵盖不匹配为空、保留有来源证据的茶饮/咖啡/餐饮/SPA商品、单次服务调用不自动扩展、回执重试不重复调用。
