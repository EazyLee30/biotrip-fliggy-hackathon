# BioTrip 项目状态与交付清单

**更新：2026-09-26**

## 产品闭环

1. 旅客输入出发/目的地、实际当地时间与时区、返程日期、既有行程和 P/J 计划密度偏好。
2. 旅客选择颜色氛围、感官环境、体验意图和服务需求；疲劳/压力自评、体验后身体/情绪反馈均为可选。
3. 如已连接 WHOOP，页面显示当前账号真实返回的恢复、HRV、静息心率、睡眠和活动周期摘要；缺失字段保持空，不以模拟指标填补。
4. 每次生成前明确展示发往各个百炼 Agent 的内容；只有用户同意后才开始真实检索和编排。
5. 百炼健康解读 Agent 把全量近期 WHOOP 相关记录转成旅行节奏筛选条件；当地服务 Agent 独立检索真实来源；旅行 Agent 经官方 FlyAI Skill 检索并生成用户可审阅的行程。
6. 旅客按站点反馈体感和情绪后，可再次调整下一段行程；保存只写入当前设备，不改变第三方订单。

## 已完成的代码

- 手机优先的响应式 Next.js 页面、PWA manifest、离线应用壳与隐私说明页。
- WHOOP OAuth connect/callback/status/disconnect 路由；OAuth state 校验、refresh token 流程、加密 HttpOnly Cookie、恢复/周期/睡眠/训练/身体测量读取。
- 服务端行程与时区校验；WHOOP、旅行与当地服务数据按不同 Agent 分流；输出必须为真实实时结果，不设示例数据 fallback。
- 百炼 Managed Agent Session/Event/SSE 服务端调用、健康 Agent 无工具检查、会话结束后删除请求。
- 每次请求前的人类可读数据去向确认，以及当前设备本地保存方案的交互。
- 参赛要求、平台接入和 WHOOP 数据范围的文档。

## 用户体验要点

- 不从 WHOOP strain 推断心理压力，不从颜色推断固定人格或情绪；颜色只用于表达旅行者自己的氛围偏好。
- P/J 只代表用户自己选择的计划组织方式，不作为心理类型测评。
- 温泉、按摩、地方饮食和医疗服务依据当地公开来源检索；不作医疗诊断、疗效承诺或营养处方。
- 跨时区节奏依据用户填入的出发/抵达当地时间和 IANA 时区计算；涉及夏令时无效时间时要求用户修正。
- 不自动预订、支付或修改现有旅行安排；固定时间项目需要保留并校验。

## 验收条件

1. 三个百炼 Agent 使用不同运行环境和最小数据权限；健康 Agent 无工具，FlyAI 仅处于旅行 Agent 环境。
2. WHOOP OAuth 回调与部署域名精确匹配；拒绝授权、token 续期失败、无效/空评分都有明确状态。
3. 任何 WHOOP、百炼或 FlyAI 未配置/报错的情况都不产生伪造数据；有效结果有可核验来源和本次检索时间。
4. 手机单手操作、触控、动态安全区、桌面布局和添加到主屏幕体验通过实际设备检查。
5. 用户逐次确认健康数据去向；断开 WHOOP 可撤销访问；关键流程不把敏感数据写进普通日志、Git 或前端代码。
6. 发布前评审隐私说明、第三方费用、WHOOP Sandbox 用户限制、百炼 Agent 账单与比赛提交授权。
