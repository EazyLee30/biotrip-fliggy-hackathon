# 系统设计

BioTrip 由移动端应用、Worker API、D1 与后台规划 Workflow 组成。产品首页位于 `/`，应用位于 `/app`；旧应用入口保留兼容跳转。

## 规划与来源

`src/lib/planning/` 统一处理阶段授权、检索、编排和结果校验。托管 Agent 与标准模型 API 实现同一 Provider 接口。任务开始时选择 Provider，运行失败不会重跑整个外部流程。

身体解读、飞猪库存、当地资料与高德出行有独立职责。身体原始记录经过专用解读后转换为旅行节奏条件；编排阶段组合已核验的来源。服务端校验模型输出的结构、日期、引用和固定安排。

## 调整与反馈

`src/lib/adjust/` 提供规则建议、前后预览、时间重排与冲突保护。基础快速调整可在不调用外部服务的情况下完成；需要时再补充真实检索与路线依据。

`src/lib/body-journey.ts` 将当天自评、独立调整和体验反馈关联到旅程。目的地当地日期、记录时间和输入来源分别保留。同一旅程内的近期反馈参与后续建议，长期偏好单独管理。

确认采用前检查账号归属、版本、固定预约与已完成活动。发生版本冲突时不覆盖用户的新安排。

## 随行助手

`src/lib/agent/` 管理会话、消息、记忆、工具调度和待确认操作。查询、清单与建议通过受限工具执行；行程变更经确认后再次校验。全局记忆设置和当次隐私要求由服务端执行。

## 运行与存储

- Workers 提供页面与 API。
- D1 保存账号、旅程、版本、清单、对话和反馈。
- Workflows 执行后台规划，客户端读取任务进度。
- WHOOP 授权信息按账户加密保存；刷新与断连由服务端协调。
- 公共影片和展示图位于 `public/`，影片 API 支持字节范围请求。
